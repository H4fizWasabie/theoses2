# Issue #541: numbered research Summary heading

[Issue #541](https://github.com/H4fizWasabie/theoses2/issues/541) reports that an Omarchy Linux research job produced a report beginning `## 1. Summary`, but the tool returned `INCOMPLETE` with the report under “Last notes.” The issue records 14 of 30 turns, 597K of 1.2M input tokens, and `stoppedBy: []`. These incident details come from the issue; the production session was not reopened here.

The report detector originally required `summary` after only non-word characters. The digit in `## 1. Summary` blocked that match, so the finished first answer and the final write-up were both treated as non-answers. `runResearch` passes `looksLikeReport` to `promptToAnswer`; the latter runs a final tool-free turn after a rejected answer, then returns `status: "none"` with the last assistant text if that answer is rejected too. `runResearch` converts `none` into an `INCOMPLETE` report and sets `complete` to false. Sources: [researcher.ts:43-46](../../packages/coding-agent/src/core/researcher.ts#L43-L46), [researcher.ts:119-137](../../packages/coding-agent/src/core/researcher.ts#L119-L137), [background-agent.ts:252-255](../../packages/coding-agent/src/core/background-agent.ts#L252-L255), [background-agent.ts:278-314](../../packages/coding-agent/src/core/background-agent.ts#L278-L314), and the [issue](https://github.com/H4fizWasabie/theoses2/issues/541).

Acceptance scope: recognize an optional decimal list number before `Summary`, including `## 1. Summary`; keep plain `Summary` accepted; keep narration without a Summary heading rejected; and verify that a finished numbered report returns `complete: true` with its report text. The current working tree already changes the detector to `/^\W*(?:\d+\.\s*)?summary\b/im` and adds the numbered-heading test, but both files are uncommitted and this note does not establish deployment or a production rerun.
