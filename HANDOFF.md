## This session: Durable Memory's write-side design resolved (grilling)

Both halves of Durable Memory's write path were grilled to resolution and closed this session — implementation has **not** started on either.

- **[Issue #49](https://github.com/H4fizWasabie/theoses2/issues/49)** (semantic layer) — the confidence-gated `save_note` design is replaced entirely by a `.md`-file semantic graph: one file per fact, closed relation-type edge vocabulary (seeded from Mino OSS's own, after studying its year-long migration from a flat FTS5 store to a graph), no durability filter (deliberately a knowledge base, not a curated ledger — mandatory dedup is the volume safety valve instead), a minimal live path for explicit "remember this" requests, and a secondary consolidation model (DeepSeek V4 Flash 0731, fp8, cheapest provider) doing fact-extraction + edge-authoring + dedup together on a keyword/turn-ceiling trigger per Channel Session. No new background-scheduler infra — confirmed via codebase search that theoses2 has none today, so the trigger piggybacks on existing end-of-turn message handling instead.
- **[Issue #50](https://github.com/H4fizWasabie/theoses2/issues/50)** (episodic layer) — new, previously undesigned. Studied [waku-agent](https://github.com/shenseanchen/waku-agent)'s episodic memory as a reference. SQLite storage (deliberately diverges from #49's `.md` files, since "what happened at time X" is a temporal range query relational rows serve better), `started_at`/`ended_at` range + summary + a lightweight array of related semantic-node ids, generated by the *same* #49 consolidation pass (not a separate one), no live path, retrieval supports both keyword search and point-in-time range query. Backfill built as a reusable pipeline rather than a one-off script.

Full resolution text (all the "why", not just the "what") lives in each issue — read them before implementing, not just this summary.
